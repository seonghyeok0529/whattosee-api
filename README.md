# whattosee-api# What to See API

What to See는 뉴스 기사 단위가 아니라 **이슈 단위로 정보를 구조화하고, 다양한 관점을 비교할 수 있도록 돕는 데이터 기반 플랫폼**입니다.  
본 레포는 해당 서비스를 위한 **백엔드 API 서버**로, 데이터 수집·가공·분석 및 서비스 로직을 담당합니다.

---

## 📌 1. 프로젝트 개요

- **프로젝트명**: What to See API
- **목적**: 뉴스 피로감, 필터 버블, 확증편향 문제를 완화하고  
  사용자가 다양한 관점을 비교하며 스스로 판단할 수 있도록 지원
- **역할**: 이슈 데이터 구조화, 콘텐츠 처리, 사용자 행동 및 성향 데이터 관리

---

## 🎯 2. 해결하고자 하는 문제

- 뉴스는 여전히 중요한 정보원이지만  
  **신뢰 저하와 피로감으로 인해 뉴스 회피 현상이 증가**
- 추천 알고리즘으로 인해  
  **특정 관점만 반복 노출되는 필터 버블 문제 발생**
- 동일 이슈에 대해  
  **언론사별·사용자별 해석 차이를 한 화면에서 비교하기 어려움**

👉 What to See는 이를 해결하기 위해  
**이슈 중심 구조화 + 관점 비교 + 사용자 해석 분석**을 결합한 플랫폼을 설계함

---

## 🧠 3. 핵심 기능

### 1) 이슈 기반 콘텐츠 구조화
- 기사 / 유튜브 영상 / 댓글 데이터를 수집
- 의미 기반 클러스터링을 통해 동일 이슈로 묶음
- 이슈별 요약, 타임라인, 쟁점 추출

---

### 2) 프레임 분석 및 관점 비교
- 콘텐츠를 프레임(책임, 갈등, 정책 등) 기준으로 분석
- 서로 다른 관점(진보/보수 등)을 구조적으로 분리
- 사용자에게 **쟁점 중심 비교 정보 제공**

---

### 3) 사용자 해석 성향 분석 (IRT)
- 댓글 데이터를 기반으로 사용자 반응을 분석
- 해석 구조를 다음 4가지 축으로 모델링

  - 유입: micro ↔ macro  
  - 원인: person ↔ system  
  - 기준: rule ↔ context  
  - 해석: fault ↔ meaning  

- XGBoost 기반 모델을 활용해  
  **Accuracy 약 75%, AUC 0.78 수준의 예측 성능 검증**

---

### 4) 공론장 및 사용자 데이터
- 이슈별 댓글 / 투표 / 의견 데이터 수집
- 사용자 행동 로그 기반 분석
- 향후 정책 및 데이터 인사이트 활용 가능

---

## 🗂️ 4. 주요 도메인 구조

- `Issue`: 이슈 단위 데이터
- `Article`: 기사 데이터
- `Clip`: 유튜브 영상
- `Comment`: 사용자 반응 데이터
- `User`: 사용자 정보 및 성향
- `Agenda`: 사용자 생성 이슈
- `FrameGroup`: 관점/프레임 그룹화 데이터

---

## 🛠️ 5. 기술 스택

- **Backend**: Node.js, TypeScript
- **Database**: PostgreSQL
- **ORM**: Prisma
- **AI/분석**:
  - OpenAI API (요약, 프레임 분석)
  - XGBoost (IRT 반응 예측)
- **Infra**: Azure App Service (배포)
